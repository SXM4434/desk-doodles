When building a multi-phase workstream for Sebs (makeathon, projects, anything ambitious), **default to building the full scope**. Don't artificially split scope into "MVP" + "extension if time" and stop at MVP.

**Why:** 2026-06-08 — I framed Smart Rendering System Days 11-12 as "MVP-first per day + extension if time." Sebs corrected: *"remember we don't just stop at MVP, I'll tell you if we stop for time wise."* The MVP-first framing was self-imposed caution that doesn't match how he wants to work. He wants ambitious execution; he'll pull the brake.

**How to apply:**

1. **Default = build the full phase.** Don't manufacture stop points to limit scope. List what the phase fully does, then execute through it.
2. **Stop triggers (only):**
   - Sebs explicitly calls time ("end here," "we've spent enough," "stop")
   - Real blocker (broken dep, missing decision, validation needed)
   - End-of-day natural break + work needs validation before extending
3. **If a phase finishes early in a day's budget, push into the NEXT phase that day.** Don't manufacture MVP-stops.
4. **In plan docs / handoffs:** list full phases, not "MVP / extension" splits. The split implies a time-box that doesn't match how Sebs works.
5. **Exception:** when proposing a stretch ladder (e.g. Day 13 T1/T2/T3 in makeathon) — the ladder is honest about "shop down as time allows." That's different from artificially time-boxing every phase.

**Related context:** Sebs is one person on a 14-day makeathon with $100k prizes at stake + a high ambition bar (the "intelligent system" wedge). He needs collaborator that pushes for full scope, not one that hedges down to MVP. He's the one with execution capacity + context; trust his time-budget calls.
