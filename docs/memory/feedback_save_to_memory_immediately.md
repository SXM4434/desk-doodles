**Rule:** When Sebs says "save to memory," "remember this," "don't forget," or any variant — STOP THE CURRENT WORK, write the memory entry NOW, add it to MEMORY.md index, THEN return to the task.

**Why:** 2026-06-04 Sebs asked multiple times during the Smart Hachure rebuild to save lessons to memory so the broken loops wouldn't repeat. I kept "promising to save" while continuing to iterate on broken work, and never actually saved anything. The pattern repeated because the lesson never got persisted. Sebs's words: "iv asked so many times to save to memory you dont do this broken loop of nothing getting fixed."

Each memory save takes ~2 minutes. Each broken loop costs an hour. The cost-benefit is not close.

**How to apply:**
- "Save this to memory" = STOP. Write the memory entry NOW. Add to MEMORY.md index. THEN continue.
- "Remember X" = same.
- "Don't forget X" = same.
- "I keep telling you X" = STRONG signal a memory should already exist for X. Write it now.
- After ANY session where Sebs visibly got frustrated about a recurring failure pattern, save a memory before the session ends. Don't wait for explicit ask.
- If multiple memory entries get suggested in one session, write them all in batch — but write them, don't promise to.

**Detection heuristic:** if Sebs has repeated the same correction or principle 2+ times in a session, a memory MUST exist for it. Check MEMORY.md. If not there, write it.

**Anti-pattern to kill:** "I'll save that to memory after I fix this." No. Save it FIRST, then fix. The save protects future-me from repeating the loop.
